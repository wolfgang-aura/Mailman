# Review page standard

Every page Mailman puts in front of a person to decide from — one run or a
batch of them — has one format. This is it. It is not a suggestion to a model;
it is generated by `mailman review` and `mailman packet`, and the parts a
generator cannot derive are validated before they render.

## The rule

**No agent hand-writes review HTML.** Not Claude, not Codex, not any model
added later. An agent writes `decision.json` in the run directory and runs the
generator. If a page needs something the format does not have, the format
changes here first, in code, with a test.

The reason is not consistency for its own sake. Every model that has been left
to compose the page has produced the same failure in a different style: the
provenance first, the question buried or missing, unchecked items filed as
caveats so they read as unfixable, and — with a batch — a wall of cards linking
to other pages, which asks the reader to open twenty-three tabs to find out
whether anything needs them at all.

## The order, and why

1. **Recommendation and one sentence.** `SEND`, `HOLD` or `DROP`, and how many
   questions block the patch.
2. **Three panels, answerable at a glance.** *What was broken*, *What we did*,
   *Is it actually fixed*. One bold sentence each, one supporting sentence, and
   a stamp naming the class of evidence.
3. **What I need from you.** Each item is a **question**, never a statement,
   with concrete options labelled A, B, C, what each one costs, and one line of
   recommendation. Blocking questions are marked. Questions are numbered, so
   the whole reply can be `1A 2B 3A`.
4. **What is still open.** Every gap carries the reason it is open and what
   closing it would cost. An item with neither is not a gap; it is work that
   was skipped, and it belongs in the questions or in the patch.
5. **Claim ledger.** Every claim on the page with the class of evidence behind
   it.
6. **The patch**, then **machine-checked** evidence beside **agent-claimed**
   prose — never interleaved, because "the gate passed" and "the agent says it
   works" are different sentences.
7. Transcripts, timeline, provenance.

The decision comes before the evidence because the evidence exists to support
the decision, not the other way round. A reader who agrees with the
recommendation stops after the panels; a reader who does not keeps going.

## Evidence classes

A claim is stamped with exactly one of these, and they are never blurred:

| Class | Means |
| --- | --- |
| `machine-checked` | a command Mailman itself ran, with a recorded exit code |
| `measured` | a number read off a recorded run, e.g. a test tally |
| `seen` | observed directly, e.g. in a capture of a screen |
| `deployed` | shipped to the target environment |
| `live-verified` | exercised in the real environment after deploying |
| `agent-claimed` | an agent's own account, with nothing behind it |
| `reasoned` | argued from the code, never executed |
| `unverified` | nobody checked, and the gap says why |

`machine-checked` and `agent-claimed` are not interchangeable. A green test
suite says nothing about a screen; a screenshot says nothing about a test.

## Writing the decision file

```bash
mailman decision RUN_ID --init
```

writes an empty `decision.json` in the run directory. Fill it in, then:

```bash
mailman decision RUN_ID
```

The validator exits 0 when the file is usable and 1 with every problem listed
at once. It refuses, among others:

- a question that does not end in a question mark
- fewer than two options, or an option with no cost
- options labelled out of order
- a gap missing its reason or its price
- an evidence class that is not in the table above
- an empty ledger

A model that cannot satisfy this has not finished thinking about the run.

## Rendering

```bash
mailman review RUN_ID              # one run
mailman packet RUN_ID RUN_ID ... --output .mailman/review-packet/index.html
```

Both exit non-zero when a run has no valid decision. The page is still written,
and it says so on its face: a missing decision is rendered as a full-width
banner naming the file and every complaint, never silently skipped.

`mailman packet` numbers questions once across the whole batch, leads with the
roll-up (how many runs, how many recommended to send, how many questions
block), and lists runs with no decision instead of dropping them.

## Visual language

`DESIGN.md` governs colour, type, spacing and the diff component, and nothing
here introduces a token outside it. The page opens from a local file with no
network: no CDN, no framework, no structural JavaScript. Every string that came
from an agent, an issue or a command is escaped.
